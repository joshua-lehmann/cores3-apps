# Fallow audit during workspace migration

The self-hosted Autoflash server embeds the checked-in `tools/autoflash/site/` Vite output. Fallow treats these generated, minified esptool-js chunks as new source after the directory move and reports unused files, circular imports and complexity in them. They are required runtime assets; their module wiring is generated by Vite. The `%BASE_URL%` HTML substitution is also resolved by Vite, not by Fallow.

The move causes Fallow's changed-file attribution to classify the existing Autoflash source as new. Its existing serial-port lifecycle and queue functions retain complexity and duplication findings; they were preserved during the move to avoid changing USB behavior without hardware regression coverage. The release discovery parsing also contains validation branches for untrusted API data. These findings remain visible and should be addressed with dedicated browser and hardware tests rather than suppressed by the migration.

For the Android support change, the small wake-lock acquisition function has intentional state guards for unsupported APIs, hidden pages, duplicate in-flight requests, an existing lock, and grants arriving after a flash ends. Lifecycle tests cover release, delayed grant cleanup and permission refusal. Splitting these guards solely to reduce the complexity metric would obscure the shared state. The generated self-hosted bundle findings remain covered by the explanation above.

The post-flash reset fix adds bounded ROM-banner observation to the existing serial handler and explicit cleanup ownership to `flashDevice`. The transaction-order tests cover delayed write completion, final-write failure, reset/reconnect failure, and ROM download text. The added guards preserve successful writes when reboot fails; their source complexity is retained rather than hidden by a wider USB lifecycle rewrite. The regenerated embedded site's minified-bundle findings remain as described above.
